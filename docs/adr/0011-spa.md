# 11. SPA

Status: accepted (2026-11-08), amended (2026-11-10)

## Context

The SPA runs in desktop browsers, on a phone and in an Android WebView, against a core on low-power hardware. v4 froze the UI on a many-band bar chart and shipped stale compiled translations after a merge.

## Decision

- **Stack.** Svelte 5 with SvelteKit 3 as a static SPA, built to precompressed assets embedded in the core binary and served from memory. No Node at runtime. It uses the hash router with relative asset and API paths, so it works at `/` and under any prefix and the core needs no fallback route. Paraglide uses a cookie or storage locale strategy, not a path prefix. v4's ingress bug (kit #14894) is fixed upstream in SvelteKit 3.0.0, untested under Home Assistant. Charts use LayerChart, the chart layer under shadcn-svelte, with canvas rendering for dense series (v4 froze on an SVG chart with many bands). Routes are code-split, so the dashboard loads only what it shows.
- **Components.** The pre-styled shadcn-svelte components and `theme.css` (glass, elevation, bevel tokens) are copied from `ediiiz/kbase` at commit `73f4cab`, recorded in one line in the SPA's docs. `components.json` settings stay as in kbase: `vega` style, `neutral` base, lucide icons, Tailwind 4, bits-ui, mode-watcher, Inter and JetBrains Mono. Updates are manual diffs. The motion and atmosphere parts of kbase's `app.css` and `animated-number` are copied too, with `active-indicator` and `app-bottom-nav` from kbase `8e6db9e` (gone by `73f4cab`), as a starting point SunReye then owns. Look, feel and navigation: ADR 21.
- **Glass.** Two levels and an ambient backdrop (ADR 21): overlay glass on menus, dialogs and sheets; lighter ambient glass on the navigation, dashboard cards and 3D label chips, over a backdrop that never repaints. The 3D canvas and the 2D flow carry no glass behind them. `prefers-reduced-transparency` and a low-power switch turn every glass surface opaque.
- **Theme.** Light and dark, dark by default, one colour preset (graphite). The brand is v3's flat sun mark in blue-600 (ADR 21).
- **Language.** Paraglide, German by default and English, with message keys and no hard-coded strings. The chosen locale is kept in local storage. Core errors are stable codes the SPA maps to text; a test reads the codes from the OpenAPI document (ADR 9) and fails on one without text in both languages. The compile step runs inside the test and build scripts, never by hand, and loads its message format plugin from `node_modules`, not the network.
- **Transport seam.** The API client, live stream included, talks through one transport interface. The first release has one adapter: plain HTTP to its own core. The Noise tunnel through the relay (ADR 16) becomes the second adapter when the relay is built, so the same build serves the cloud web app.
- **Tests.** `bun test` for logic and Vitest browser-mode component tests (`*.svelte.test.ts`), both in the gate. End-to-end journeys run deliberately, outside the gate. A test that asserts on source text is banned.
- **Rendering.** Everything renders from the capabilities document (ADR 9). No brand or profile name appears in a conditional.
- **Dashboard.** Once a scene exists (ADR 20), the dashboard opens on the live 3D scene; the 2D power flow serves without a scene, without WebGL2 or with the low-power switch on, and a toggle switches between them per browser. The 3D canvas is opaque.
- **Screens, first release.** First-run setup (admin password, plant timezone and location, discovered devices to confirm, proposed topology, PV layout); live dashboard with power flow; history and statistics; the solar forecast with its strings (ADR 17); devices and settings (connections, setting writes with their outcome, the write log); tariff and savings (ADR 12); the EVCC card; status and logs.

## Considered options

- **Server-rendered with Node.** Rejected: a runtime on the device for no benefit.
- **Linking kbase as a workspace dependency.** Rejected: the build would depend on a sibling checkout.
- **Glass everywhere.** Rejected: blur behind live-updating content is the worst case for paint time on weak devices. Ambient glass sits only over the static backdrop or over the 3D canvas, which repaints only on ticks.

## Consequences

The copied components drift from kbase unless someone diffs them. kbase's `DESIGN.md` (917 lines) is not carried over; the SPA keeps a short design file with only the rules that decide behaviour.
