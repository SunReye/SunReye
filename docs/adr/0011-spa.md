# 11. SPA

Status: proposed (2026-11-08)

## Context

The SPA runs in desktop browsers, on a phone and in an Android WebView, against a core on low-power hardware. v4 froze the UI on a many-band bar chart and shipped stale compiled translations after a merge.

## Decision

- **Stack.** Svelte 5 with SvelteKit 3 as a static SPA, built to precompressed assets embedded in the core binary and served from memory. No Node at runtime. It uses the hash router with relative asset and API paths, so it works at `/` and under any prefix and the core needs no fallback route. Paraglide uses a cookie or storage locale strategy, not a path prefix. v4's ingress bug (kit #14894) is fixed upstream in SvelteKit 3.0.0, untested under Home Assistant. Charts use LayerChart, the chart layer under shadcn-svelte, with canvas rendering for dense series (v4 froze on an SVG chart with many bands). Routes are code-split, so the dashboard loads only what it shows.
- **Components.** The pre-styled shadcn-svelte components and `theme.css` (glass, elevation, bevel tokens) are copied from `ediiiz/kbase` at commit `73f4cab`, recorded in one line in the SPA's docs. `components.json` settings stay as in kbase: `vega` style, `neutral` base, lucide icons, Tailwind 4, bits-ui, mode-watcher, Inter and JetBrains Mono. Updates are manual diffs. The kbase shell, layout and status chip are not copied; SunReye writes its own small layout vocabulary.
- **Glass.** Only on overlays and the shell (dialogs, sheets, the sidebar). Live tiles and the power-flow diagram are opaque, so nothing blurs behind content that repaints every second. `prefers-reduced-transparency` and a low-power switch turn every glass surface opaque.
- **Theme.** Light and dark, one colour preset (graphite). The indigo brand colour is a placeholder until SunReye has its own.
- **Language.** Paraglide, German by default and English, with message keys and no hard-coded strings. Core errors are stable codes the SPA maps to text. The compile step runs inside the test and build scripts, never by hand.
- **Rendering.** Everything renders from the capabilities document (ADR 9). No brand or profile name appears in a conditional.
- **Screens, first release.** First-run setup (admin password, plant timezone, discovered devices to confirm, proposed topology); live dashboard with power flow; history and statistics; devices and settings (connections, setting writes with their outcome, the write log); tariff and savings (ADR 12); the EVCC card; status and logs.

## Considered options

- **Server-rendered with Node.** Rejected: a runtime on the device for no benefit.
- **Linking kbase as a workspace dependency.** Rejected: the build would depend on a sibling checkout.
- **Glass everywhere.** Rejected: blur behind live-updating content is the worst case for paint time on weak devices.

## Consequences

The copied components drift from kbase unless someone diffs them. kbase's `DESIGN.md` (917 lines) is not carried over; the SPA keeps a short design file with only the rules that decide behaviour.
